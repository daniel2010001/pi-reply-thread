# reply-thread — index the replies one prompt produces in a Pi / Gentle Shell session

A Pi package (`pi-reply-thread`) that groups every final assistant reply under the prompt that
started it, labels what triggered each reply (the prompt, a background job, a subagent), gives each
reply an ordered and a unique ID, and keeps the open asks of earlier replies visible.

## Specs

- S1 — Reply index. Owner (verbatim): "quisiera hacer algo así como un "índice" de las respuestas, esto porque veo que a menudo gentle-ai lanza respuestas, pero acto siguiente, como si estuviera esperando alguna otra cosa, responde otra cosa, algo como: promp -> respuesta 1 -> termina algún worker o job -> respuesta 2 -> termina otro job -> respuesta 3, esto puede hacer que el "hilo" de la respuesta se pierda, por ejemplo: la respuesta 3 espera acciones o decisiones de la respeusta 1 o de la 2, entiendes?"
  Approved shape (owner: "me gusta"): one thread per user prompt holding every final reply until the next prompt; each reply shows its trigger (`prompt`, `job: <label>`, `worker: <label>`, other session messages); no extra model call; nothing enters the model context; works after `/resume` because it is rebuilt from the session branch.
- S2 — Two IDs per reply. Owner (verbatim): "promp -> response 1 (algún tipo de identificador, quisas dos, algo como uno ordenado y otro único) -> response 2 -> ..."
  Approved shape: ordered ID `P<prompt>.R<reply>` (for example `P12.R2`); unique ID = the 8-hex Pi session entry ID of that assistant message (for example `a1b2c3d4`).
  ```
  P12  "buscá si existe…"                   12:04
   ├ P12.R1  a1b2c3d4  prompt        ⚠ espera tu decisión
   ├ P12.R2  e5f6a7b8  job: tests
   └ P12.R3  c9d0e1f2  worker: docs
  ```
- S3 — Open asks stay visible. Approved: deterministic detection (no model) of replies that wait on the owner — a question line outside code, a "Needs your decision" result, or the owner's language equivalents; a widget above the editor appears only when the current prompt has 2 or more replies and names the replies still waiting.
- S4 — Reader view. Approved: `/replies` lists the threads; choosing a reply opens it in full in a scrollable viewer; a reply can also be opened directly by either ID. Text only: no audio in this package.
- S5 — Community plugin. Owner (verbatim): "quisiera lo haga para que sea algo así como un plugin de la comunidad de gentle-ai, podemos?" → a standalone Pi package (`pi-package` keyword) that works in plain Pi and inside Gentle Shell. Publishing to npm and the gentle-ai issue happen only with the owner's explicit OK.
- S6 — Separate projects. Owner (verbatim): "quisas separemos los proyectos ya que veo que hacemos muchas cosas en uno solo" → this repository holds the index only; the spoken reader is a separate package (see Log L4).
- S7 — Card look. Owner (verbatim): "me gusta, pero la nueva ventana no termina de gustarme, podríamos darle más estética? quisas usar los themas de pi/gsh, se puede?" → chose "Tarjeta (rediseño completo)": rounded frame with title and counts, prompt rows on the user-message background, `├ └` tree, a colour per trigger kind, selected row on `selectedBg`, scrollbar, and a viewer card header with the open asks on top. Every colour is a theme token of the active Pi/gsh theme; nothing hardcoded.
- S8 — Pending central. Owner (verbatim): "algo que no termina de gustar es que las preguntas se quedan como "pendientes", qué podemos hacer al respecto? las respuestas deben ser explicitas? [...] quisiera tener algo así como un "copiar y pegar" para las pregutnas y poderlas responder, qué dices? también creo que puede haber preguntas repetidas, como pedir en una respuesta algo y luego volver a preguntas en otra respuesta, qué pasa con esto? si respondo en un lado las otras también se responden? o mejor por qué no tenemos algo así como una "central" para todo esto, qué dices?" Decisions: close "Solo explícito (recomendado)"; repeats (verbatim): "podemos hacer algo así como tener id para las preguntas? algo como a1b2c3d4 y que las preguntas hagan referencia a otras? algo así como: a2 es precontinuación de a1."; start: "Sí, hacela". Design in L19.
- S9 — English everywhere. Owner (verbatim): "Algo que noto es que estamos mezclando entre ingles y español, usar siempre en ingles, esto incluye los agentes/skills/etc." → package UI, paste text, keys, docs, agent instructions and handoffs in English. Owner quotes in this document stay verbatim (ODD rule). Detection keeps the Spanish markers: they read the agent's Spanish replies.
- S10 — Clear, optional section rule. Owner (verbatim): "sí, pero anota esto, cosa que sea fácil de leer, quisas en el readme, pero hay que ser MUY claros con esto, si vamos a compartir o publicar este plugin las personas que lo usen puede que se pregunten sobre esto y quisas no lo entiendan, cosa como: "por qué si en cada sección de las repuestas hay preguntas no se reflejan en el menú?" cosas como esto quisiera evitar, por eso quisiera que sea muy claro, o si se puede hacer algo como una opción para que así sea, pero no sé si será posible, se puede?"

- L19 (2026-10-25, design for T11-T13, parent decision; workers follow it):
  - Question IDs: ordered `P<prompt>.R<reply>.Q<n>` (n = 1-based position in `Reply.openAsks`), unique `<reply entryId>.<n>` (e.g. `a1b2c3d4.2`). `/replies <question id>` opens its reply (both forms, case-insensitive ordered).
  - Answered: derived, no stored state — an ask is answered when a later user prompt on the branch (not a gentle-agents wake) contains its ordered or unique ID. Answering through the central pastes such a quote, so sending it closes the ask.
  - Dismissed, linked: `pi.appendEntry("reply-thread.ask", data)` (custom entry, outside the model context, on the branch, survives /resume). `data` is `{ action: "dismiss" | "reopen", ask: <unique id> }` or `{ action: "link" | "unlink", ask: <unique id>, continues: <unique id> }` (ask = newer, continues = older). Rebuilt in branch order; later entries win.
  - Chains: linked asks form a chain; answering or dismissing any member closes the whole chain. The central shows a chain once, on its newest member, with `↺ <ordered ids of the older members>`.
  - Repeat suggestions (never automatic): an open ask that is not linked gets a suggested older open ask when, after normalization (lowercase, inline code and punctuation removed, spaces collapsed), the texts are equal or their word sets (words longer than 3 letters) have Jaccard ≥ 0.6; the newest such older ask is suggested and shown as `≈ <ordered id>`; `l` confirms the link, `u` unlinks.
